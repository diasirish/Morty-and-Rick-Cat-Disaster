# Муха управляет Морти

Ветки находятся в одном репозитории и одной рабочей папке:

- `learn`: игра и исходные учебные заготовки RL.
- `fruitfly/demo`: та же игра плюс готовый адаптер `fly_demo.py`.

Перед переключением сохрани изменения коммитом или stash. Команды:

```sh
git switch learn
git switch fruitfly/demo
```

## Запуск демо

Из папки игры, на ветке `fruitfly/demo`:

```sh
.venv-fly/bin/python fly_demo.py
.venv-fly/bin/python fly_demo.py --headless --episodes 3
```

Окно закрывается крестиком или Escape. Справа от игры находится панель
с аватаркой мухи, реальными импульсами сети и частотами выходных нейронов в Гц. Первый запуск может потратить время на компиляцию Numba.

Данные лежат рядом с игрой, в `../fruit_fly/brain-data`. Для другого пути:
`--data /полный/путь/brain-data`. При отсутствии данных flybrain предложит
автоматическую загрузку примерно 260 МБ. Python-окружение `.venv-fly` отдельно
от учебного `.venv` и не хранится в Git.

Для установки на другой машине:

```sh
python3 -m venv .venv-fly
.venv-fly/bin/python -m pip install -r requirements-fly.txt
```

## Что здесь сделано

1. `encode_scene` читает координаты котов относительно Морти. Это вручную
   спроектированный интерфейс восприятия, **не распознавание картинки**.
2. Положение цели возбуждает LC10a, близкая угроза — LC4/LPLC2 на соответствующей
   стороне. Выбор нейронов опирается на примеры upstream fly.ai.
3. `FlyBrain.step` моделирует распространение импульсов в фиксированной сети.
   Один шаг мозга — 20 мс; четыре шага соответствуют четырём кадрам игры.
4. Усреднённая активность DNa02 задаёт движение, DNp01 — нажатие лая.
   Связь «реакция мухи → кнопка игры» задана нами; муха сама не знает, что такое лай.
5. Игра исполняет действие и выдаёт награду. В этом демо награда только
   записывается: никаких обновлений весов и RL-обучения здесь нет.

Это эксперимент с моделью нервной системы, а не доказательство полноценного
поведения живой мухи или гарантированно сильный игровой агент.

## Сравнение

```sh
.venv-fly/bin/python fly_demo.py --headless --episodes 3 --seed 0 --report runs/fly.json
.venv-fly/bin/python fly_demo.py --headless --episodes 3 --seed 0 --controller blind --report runs/blind.json
.venv-fly/bin/python fly_demo.py --headless --episodes 3 --seed 0 --controller random --report runs/random.json
```

`blind` использует тот же мозг без игровых входных сигналов. Так можно проверить,
меняет ли восприятие поведение, а не просто наблюдать внутренний шум сети.
Сравнивай score, reward, won и action_counts на одинаковых seed и лимитах.
Три эпизода — проверка запуска, а не статистически надёжный вывод о качестве.

## Учебный маршрут

На `learn` решения `rl/networks.py`, `rl/replay_buffer.py`, `rl/agent.py`
остаются за тобой. Сначала разберём state/action/reward и случайный baseline,
затем можно самостоятельно сделать табличный Q-learning на упрощённом состоянии,
свою небольшую нейросеть, replay buffer и DQN по картинке. Разбор демо не требует
заранее раскрывать решения этих заданий.

Источник модели: https://github.com/alextitonis/fly.ai (пакет `flybrain==0.1.0`).

## Живая панель мозга

`fly_panel.py` рисует панель шириной 420 пикселей справа от игры. Каждый из
283 показанных узлов соответствует реальному нейрону; вспышка возникает только
после его импульса. Позиции схематические, линии — существующие синаптические
связи между выбранными узлами. Наведи мышь на узел, чтобы увидеть тип, сторону
и индекс нейрона в модели.

Бирюзовые узлы — остальные выбранные нейроны, янтарные — сенсорные входы,
розовые — моторные выходы. Число SPIKES показывает все импульсы всей сети за
последние 80 мс модельного времени, включая повторные импульсы одного нейрона.
Плавное свечение — визуальное послесвечение этих событий, а не новые импульсы.
SENSE показывает входные сигналы, DNa02 / DNp01 — сглаженные частоты выходов,
MORTY — выбранную агентом команду. Панель не входит в наблюдение RL-окружения.

Сохранить кадр вместе с панелью без открытия окна:

```sh
.venv-fly/bin/python fly_demo.py --headless --max-steps 180 --snapshot runs/panel.png
```

Аватарка: `visuals/fruitfly-avatar.png`; исходный промпт и способ генерации —
`visuals/fruitfly-avatar-prompt.md` (встроенный image_gen).

Контрольный прогон с панелью сохранил результат seed 0: 20 очков, 603 решения
и то же распределение действий [136, 70, 74, 104, 115, 104], что и до визуализации.

## Варианты оформления

В главном меню `main.py` появился пункт **Designs**. В запущенном демо нажми
**F1**, чтобы открыть то же меню и приостановить игру на время выбора.

- **Original** — исходный двор, HUD и первый минималистичный дашборд.
- **Backyard Deluxe** — тёплый свет, тени персонажей, рамки HUD и деревянный
  мухопульт Ларисы с бумажным портретом и приборными шкалами.
- **Midnight Mayhem** — ночной двор, луна, холодные эффекты лая и ночная палитра пульта.

В меню есть предпросмотр. Выбирай мышью или стрелками; Enter / Apply Design
сохраняет выбор в `runs/design.json`, Escape отменяет. При первом запуске выбран
Backyard Deluxe. Предпочтение общее для ручной игры и демо.

```sh
.venv-fly/bin/python fly_demo.py --menu
.venv-fly/bin/python fly_demo.py --design original
.venv-fly/bin/python fly_demo.py --design midnight
```

Флаг `--design` меняет оформление только этого запуска. Пункт меню сохраняет
выбор для следующих запусков. `game/design.py` отвечает за темы, меню выбора
и оформленную отрисовку. Движок, столкновения, награды, скорость и оригинальные
файлы изображений не изменены. У FlyPanelEnv отдельный `view_renderer`:
наблюдения RL по-прежнему строит оригинальный Renderer.

34 теста прошли: в том числе пиксельное совпадение Original с прежним Renderer,
неизменность RL-наблюдений во всех темах, сохранение / отмена и выбор мышью.
